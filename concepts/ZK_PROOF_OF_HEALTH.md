# ZK Proof of Node Health

## Problem

Blockchain oracles expose infrastructure details (IP addresses, node topology, measurement methodology) to every consumer. A DeFi protocol querying "is Base safe to execute?" shouldn't need to know how the oracle measures latency — only that the measurement is correct and the measurer is honest.

## Current State: ZK-lite (Phase 0, Deployed)

The x402 Health Oracle already issues verifiable health proofs via `/api/health-proof`:

```json
{
  "proof": {
    "commitment": "2992b09877ed4d30...",
    "salt": "9d9631b4e07ed881...",
    "layersBitmap": 70,
    "ts": 1788547017945,
    "version": 1
  }
}
```

**How it works:** HMAC-SHA256 commitment over the 8-layer security bitmap (PQC session, GPU/UA check, Frankenstein detection, Spearman correlation, variance bounds, Argon2 PoW, entropy threshold, jitter verdict). The commitment proves the node passed N of 8 layers at timestamp T without revealing which specific metrics were measured.

**Limitation:** HMAC is trusted-verifier — the server holds the key. A malicious oracle could forge commitments.

## Phase 1: zkVM Proof Circuit (risc0 / SP1)

Replace HMAC with a zero-knowledge proof generated inside a zkVM:

```
┌─────────────┐     ┌──────────────────┐     ┌────────────────┐
│ eBPF Sensor  │────▶│ zkVM Prover       │────▶│ On-chain        │
│ (P99, revert │     │ (risc0 guest)     │     │ Verifier        │
│  ratios, gas)│     │                    │     │ (Solidity)      │
│              │     │ prove:             │     │                  │
│              │     │ P99 < threshold    │     │ verify(proof,   │
│              │     │ revert < 0.30      │     │   public_inputs)│
│              │     │ uptime > 99%       │     │                  │
└─────────────┘     └──────────────────┘     └────────────────┘
```

**Circuit inputs (private):**
- Raw P99/P95 latency values per chain
- Revert ratio numerator/denominator
- Gas pressure readings
- Measurement timestamps

**Public outputs:**
- Boolean: `health_ok` (all thresholds met)
- Commitment to measurement window (start_ts, end_ts)
- Prover public key hash

**What this proves:** "A node with key K measured N chains over window [T1,T2] and ALL were within safe thresholds" — without revealing exact latency values, which chains were slowest, or the measurement methodology.

## Phase 2: On-chain Verification

Deploy a Solidity verifier contract (auto-generated by risc0/SP1) on Base:

```solidity
interface IHealthVerifier {
    function verifyProof(
        bytes calldata proof,
        bytes32 commitmentHash,
        uint256 windowStart,
        uint256 windowEnd
    ) external view returns (bool);
}
```

DeFi protocols call `verifyProof()` before executing trades. Cost: ~300K gas for STARK verification, amortized via proof batching.
